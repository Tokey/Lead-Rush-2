# B48: Unity 6000.5 / HDRP 17.5 upscaling and latency

## Findings (research first)

The project is Unity 6000.5.0f1 with HDRP 17.5.0. HDRP provides Unity's
resolution scaling/upscaling path (including STP where supported by the active
HDRP version), but DLSS, DLAA, NVIDIA Reflex and vendor frame generation are not
automatic settings exposed by the package. They require a vendor integration or
Unity-supported package/plugin and platform capability checks.

Sources:

- [Unity HDRP package documentation](https://docs.unity.com/en-us/engine/6000.0/manual/packages-list/packages-all/pack-core/com-unity-render-pipelines-high-definition)
  (HDRP scope and package versioning).
- [NVIDIA DLSS](https://developer.nvidia.com/rtx/dlss) (DLSS Super Resolution,
  DLAA, Frame Generation, Reflex relationship and Streamline).
- [NVIDIA Streamline](https://github.com/NVIDIAGameWorks/Streamline) (open-source
  integration framework and per-feature plugins).
- [AMD FidelityFX Super Resolution 3](https://gpuopen.com/fidelityfx-super-resolution-3/)
  (FSR upscaling/frame interpolation, DX12 requirements and SDK).
- [Unity license](https://unity.com/legal/terms-of-service/software) and the
  [NVIDIA Streamline license](https://github.com/NVIDIAGameWorks/Streamline/blob/main/LICENSE.txt):
  review the exact package terms before shipping a plugin or redistributing
  binaries. AMD FidelityFX SDK is MIT-licensed per its repository.

## Support matrix and settings

| Setting | Native in this project? | Exposure |
|---|---|---|
| Native / STP | Use HDRP's supported dynamic-resolution path; verify the 17.5 frame-settings API in Unity before coding | `Upscaler: Native, STP`; default Native |
| DLSS / DLAA | No built-in project API; NVIDIA plugin/Streamline integration required, RTX only | `Upscaler: DLSS Quality/Balanced/Performance`, `DLAA`; disable options when provider unavailable |
| FSR | No built-in project API; add AMD FidelityFX SDK/plugin and validate motion vectors/depth | `Upscaler: FSR Quality/Balanced/Performance`; available on DX12 capable hardware |
| NVIDIA Reflex | Plugin/Streamline integration, not an HDRP checkbox | `Low Latency: Off/On/On+Boost`; show only when integration and NVIDIA GPU report support |
| Frame generation | DLSS FG/Streamline or FSR 3 plugin; not free from HDRP alone; needs motion vectors and UI composition policy | `Frame Generation: Off/On`; default Off and require a measured base FPS floor |

Do not silently substitute an unsupported mode: show “Unavailable on this GPU /
API” and retain the prior mode. Do not enable frame generation below 60 real
rendered FPS; generated frames must not be used to claim input-latency gains.
Keep VSync and frame limit separate.

## Implementation order

1. Add an `UpscalerBackend` abstraction and capability probe; keep the current
   native path as the no-plugin implementation.
2. Add telemetry fields for real render FPS, presented FPS, GPU time and input
   latency. Compare each map in the P3 warmup/combat/worst-state protocol.
3. Integrate one vendor package only after its Unity 6000.5/HDRP 17.5 support,
   redistribution terms and DX12/driver matrix are confirmed. Keep the plugin
   behind compile symbols and a runtime capability check.
4. Expose the settings through B44 without coupling the UI to vendor classes.
   Quality presets select Native/Quality, not DLSS/FSR, unless the backend is
   proven available.

Acceptance: a supported mode changes internal/rendered resolution as expected,
unsupported modes are disabled with an explanation, frame-generation reports
base and presented FPS separately, and every map has a before/after P3 record.
