# P3 - LR2 performance pass

LR2 has an FPS display, frame-limit/quality settings, HDRP ray-tracing controls,
and a batch QA bot, but it does not yet produce a repeatable per-map frame-cost
report. The performance pass should establish baseline evidence before tuning.

## Benchmark protocol

1. Run the visible player on each map at 1120x630 for a stable warm-up, then
   capture 30 seconds at 1920x1080 with the standard development graphics preset.
2. Record 99th percentile, median, and average frame time; CPU and GPU frame time
   separately; RAM; draw calls; batch instances; triangles; and HDRP shadow/decal
   counts where available.
3. Record three states per map: menu/idle, contested combat, and worst-known
   visual path (rain, smoke, muzzle flashes, decals or dense foliage).
4. Repeat after a 60-second warm-up to avoid shader/load-spike bias. Preserve
   hardware, driver, resolution, quality preset, VSync, FPS limit and scene names
   in the report.
5. Use Unity Profiler/FrameTiming APIs, not only wall-clock FPS, because 60 FPS
   can hide a GPU-bound frame or a single 100 ms hitch.

## LR2 top-cost review order

- animated Kinemation rigs and RetargetProxy updates
- HDRP volume/weather/rain/shadow work
- decals and pooled impact/blood particles
- distant bots and per-bot NavMesh/LOS queries
- map scene triangles and overdraw
- reverb/ambience and audio voice allocation
- managed allocations from QA or debug text

## Report format

Write `Docs/AI_Collaboration/specs/P3-results.md` after the first run with:

- one table per map and state
- median/99th CPU ms and GPU ms
- bottleneck callsite or profiler module
- top five allocated/costly systems
- accepted thresholds and a concrete follow-up issue

Proposed first-pass target: no sustained frame slower than 33.3 ms at 1080p on
the reference hardware, and no 99th-percentile over 50 ms outside documented
shader warmup. Targets become pass/fail only after the user supplies reference
hardware and a reference run.
